# Moodstay content-generation instructions

When the user supplies only a lodging name, treat it as a request to continue the production workflow in [`docs/reel-production-workflow.md`](docs/reel-production-workflow.md), not merely write a standalone script. Create or resume a property project, research current differentiators, request roughly 8–15 property photos when they are not supplied, write the story before final image selection, then build a natural-beat pack of factual real-photo anchors and reference-grounded first-person AI stills (normally 16–24 edit cuts). Persist the narration, each 9:16 still, cut map, source manifest, and one video-generation prompt per unique still in that project. Usually give each cut a distinct image, but intentionally reuse a memorable clip later when it strengthens the story or creates a visual callback. Then use `tools/prepare_reel_timing.py` to lock one Typecast take before motion generation, wait for the user-generated clips, and use `tools/render_reel.py` for frame-aligned edits, subtitles, and final rendering. Do not ask for a brief unless a missing detail blocks useful work.

Keep every phase explicit and truthful: a source page is not proof of image redistribution rights; a prompt is not a generated clip; a render command succeeding is not final QA. Never claim a stage is complete without its named artifact/check. Do not commit photo/video assets to a public GitHub repository unless the user's rights specifically permit that redistribution. Store reusable prompts, scripts, source links, selection rationale, rights status, and resume state in Git-tracked project files. Keep API keys out of Git and chat.

Thumbnail rule: after the final reel passes QA, propose exactly five short cover-copy options that use its hook. The user selects one. Then create and deliver the actual 9:16 thumbnail image together with the final reel, using the final first frame as background: copy block at true horizontal-and-vertical center, extra-bold white Korean type with thick black outline/shadow, and `[광고]` at top right. Never select the final cover copy on the user's behalf.

Use `projects/vivacostay-reel/` as the reference implementation and `docs/full-reproduction-guide.md` as the end-to-end manual. Send the whole `narration.txt` in one Typecast request; never synthesize caption fragments separately. Keep Typecast API silence compression disabled because compressed audio can diverge from returned character timestamps. Quantize cumulative caption starts to whole output frames once, then use those same boundaries for video cuts and ASS caption events. If a voice stretches a Korean word, rewrite it naturally and regenerate the continuous take instead of splicing syllables.

Visual direction for every Moodstay reel: make it feel like a real guest's visit, not a polished virtual tour. Write the story first, then start from the user's strongest real property photos and preserve them with clean 9:16 crops whenever they already express the beat. Use reference-grounded first-person AI stills only for important actions or transitions the supplied photos cannot show; there is no quota, and do not create near-duplicates by merely adding a hand. The account owner is a fictional travel persona, so subjective discoveries and reactions may support the story, but do not force unnecessary companions, conflicts, or discovery stories. Never invent or alter objective property facts such as amenities, layout, views, location, prices, or inclusions. Keep the source scene, people, furniture, and objects stable in image-to-video. Start with one short, slow, single-direction camera prompt such as `천천히 줌인`; add `원본 장면 유지` only if a test changes the scene. Build energy with shot order, hard cuts, and captions. Intentional callbacks reuse the existing generated clip rather than requiring duplicate generation.

Non-negotiable output rules:

- Never say the lodging's proper name in the narration. The unanswered identity is part of the comment strategy.
- Do not append a direct comment CTA such as “여기 어딘지 궁금하면 댓글로 물어봐요,” “댓글에 정보 남겨주세요,” or “DM 보내드릴게요.” The supplied references do not use those endings.
- End with an experience-style personal verdict that resolves the story, not a question or sales CTA.
- Use the user's supplied examples as structural references, not text to copy.
- Research the property's actual differentiators; do not invent amenities, prices, inclusions, seasonal availability, or other objective property facts.
- Keep all narration clean and ready to paste into Typecast. Keep the property name and citations outside the spoken block.
