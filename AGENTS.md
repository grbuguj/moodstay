# Moodstay content-generation instructions

When the user supplies only a lodging name, treat it as a request to continue the production workflow in [`docs/reel-production-workflow.md`](docs/reel-production-workflow.md), not merely write a standalone script. Create or resume a property project, research current differentiators, request roughly 8–15 property photos when they are not supplied, write the story before final image selection, then build a 20-cut pack of factual real-photo anchors and reference-grounded first-person AI stills. Persist the narration, each 9:16 still, cut map, source manifest, and one video-generation prompt per cut in that project. Usually give each cut a distinct image, but intentionally reuse a memorable image later when it strengthens the story or creates a visual callback. Then wait for the user-generated clips and use `tools/render_reel.py` for Typecast narration, timing-aligned edits, subtitles, and final rendering. Do not ask for a brief unless a missing detail blocks useful work.

Keep every phase explicit and truthful: a source page is not proof of image redistribution rights; a prompt is not a generated clip; a render command succeeding is not final QA. Never claim a stage is complete without its named artifact/check. Do not commit photo/video assets to a public GitHub repository unless the user's rights specifically permit that redistribution. Store reusable prompts, scripts, source links, selection rationale, rights status, and resume state in Git-tracked project files. Keep API keys out of Git and chat.

Thumbnail rule: after the final reel passes QA, propose exactly five short cover-copy options that use its hook. The user selects one. Then create and deliver the actual 9:16 thumbnail image together with the final reel, using the final first frame as background: copy block at true horizontal-and-vertical center, extra-bold white Korean type with thick black outline/shadow, and `[광고]` at top right. Never select the final cover copy on the user's behalf.

Visual direction for every Moodstay reel: make it feel like a real guest's visit, not a polished virtual tour. Write the story first, then make first-person AI stills the main visual language for experiential beats—normally about 60–80% of a 20-cut reel. Use real property photos as factual anchors at moments that prove the actual exterior, room layout, amenity, food, or view; use those real references for every AI POV still. The account owner is a fictional travel persona: invented discoveries, relationship dynamics, friends, work conversations, and subjective reactions are allowed when they make the story compelling. AI POV and narration must never invent or alter objective property facts such as amenities, layout, views, location, prices, or inclusions. Keep the source scene, people, furniture, and objects still in image-to-video. The default camera is locked; if motion helps, use only a nearly imperceptible, slow, steady 2D move. Build energy with shot order, hard cuts, and captions—not camera movement or object animation. Intentional image callbacks are allowed when they reinforce the story.

Non-negotiable output rules:

- Never say the lodging's proper name in the narration. The unanswered identity is part of the comment strategy.
- Do not append a direct comment CTA such as “여기 어딘지 궁금하면 댓글로 물어봐요,” “댓글에 정보 남겨주세요,” or “DM 보내드릴게요.” The supplied references do not use those endings.
- End with an experience-style personal verdict that resolves the story, not a question or sales CTA.
- Use the user's supplied examples as structural references, not text to copy.
- Research the property's actual differentiators; do not invent amenities, prices, inclusions, seasonal availability, or other objective property facts.
- Keep all narration clean and ready to paste into Typecast. Keep the property name and citations outside the spoken block.
